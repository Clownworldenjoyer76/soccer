Legacy 3-Way Juice Calibration

PURPOSE

The league `3way_juice.csv` files are legacy calibration inputs.

They are still used by:

`docs/win/soccer/scripts/02_juice/apply_juice.py`

Their output is diagnostic only. They do NOT control the authoritative production `engine_*` probabilities or fair odds.

Production pricing comes from the runtime Dixon-Coles engine using exact match xG values and the league rho configuration.


WHAT A BAND MEANS

A band is a range of model win probabilities.

For example:

- 0.20-0.25 = outcomes with model probabilities around 20%-25%
- 0.60-0.65 = outcomes with model probabilities around 60%-65%

The historical calibration grouped outcomes with similar probabilities and assigned a side-specific `extra_juice` value.


HISTORICAL SOURCE / PROVENANCE

The `3way_juice.csv` values were derived from approximately 20 years of historical data during prior analysis.

The original historical dataset, calculation notebook/script, and exact generation trail were not retained.

Therefore:

- the current CSV values are retained legacy calibration data;
- their historical source is known only at this high level;
- the values cannot currently be independently reproduced from repository artifacts;
- no more precise provenance should be claimed unless the original source data or calculation artifacts are recovered.


CURRENT CODE SIGN CONVENTION

The current implementation does NOT subtract `extra_juice`.

For each 1X2 side, `apply_juice.py` uses:

`p_raw_adjusted = p_model + extra_juice`

It then renormalizes the three adjusted values:

`p_adjusted_side = p_raw_adjusted_side / sum(p_raw_adjusted_home, p_raw_adjusted_draw, p_raw_adjusted_away)`

Therefore `extra_juice` is a SIGNED calibration adjustment:

- positive value -> raises that side before renormalization;
- negative value -> lowers that side before renormalization.

The code always ADDS the stored signed value.

Any older documentation saying to always subtract `extra_juice` is obsolete and does not describe the current implementation.


IMPORTANT: DIAGNOSTIC ONLY

The resulting legacy diagnostic fields are retained for analysis/compatibility.

They are not the production pricing source.

Authoritative production fields are the Dixon-Coles `engine_*` probabilities and their corresponding fair decimal odds.
