# Legacy 3-Way Juice Method

## Status

This method is still executed by:

`docs/win/soccer/scripts/02_juice/apply_juice.py`

It produces legacy diagnostic 1X2 adjustment fields only.

It does NOT replace or modify the authoritative production Dixon-Coles `engine_*` probabilities or fair odds.

## Inputs

For each match:

- raw model home probability
- raw model draw probability
- raw model away probability
- league/side `3way_juice.csv`
- each side's stored signed `extra_juice`

## Step 1 - Start with raw model probabilities

For each side:

`p_model = raw model probability`

The three raw model probabilities are expected to represent Home / Draw / Away.

## Step 2 - Interpolate the stored legacy adjustment

For each side independently, `apply_juice.py` interpolates `extra_juice` from that league's `3way_juice.csv` using:

- `side`
- `fair_prob`
- `extra_juice`

The interpolation is based on the raw model probability for that side.

## Step 3 - Apply the signed adjustment

Current code uses:

`p_raw_adjusted = p_model + extra_juice`

This is the canonical implementation.

`extra_juice` is a signed value:

- positive values increase the side before renormalization;
- negative values decrease the side before renormalization.

Do not automatically subtract the stored value.

## Step 4 - Renormalize 1X2

After all three side-specific adjustments:

`total = p_home_raw_adjusted + p_draw_raw_adjusted + p_away_raw_adjusted`

Then:

`p_home_adjusted = p_home_raw_adjusted / total`

`p_draw_adjusted = p_draw_raw_adjusted / total`

`p_away_adjusted = p_away_raw_adjusted / total`

The resulting three diagnostic probabilities must sum to approximately 1.

## Step 5 - Diagnostic output only

The adjusted values are retained as legacy diagnostic `juiced_*` fields.

They are not used as the authoritative production probability source.

Production pricing uses the exact-xG Dixon-Coles engine in `apply_juice.py`.

## Historical calibration provenance

The `3way_juice.csv` values were derived from approximately 20 years of historical data during prior analysis.

The original source dataset and generation calculations were not retained.

As a result, the current legacy calibration tables cannot be independently reproduced or reverified from repository artifacts alone.

They should be treated as retained historical calibration inputs unless and until the original source/calculation trail is recovered.

## Canonical distinction

Legacy diagnostic path:

`raw model probability -> signed extra_juice adjustment -> renormalize -> juiced_* diagnostic fields`

Production pricing path:

`exact home_xg + exact away_xg + league rho -> runtime Dixon-Coles -> engine_* probabilities -> fair decimal odds`

The production path is authoritative.
